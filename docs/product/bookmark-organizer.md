# Bookmark Organizer 产品定义

文档状态：产品定义来源（Source of Truth）  
产品状态：MVP `Ready for Delivery`；文件导入 `Defining`<br>
当前可用性：`Not built`  
适用版本：MVP 1.0  
最后更新：2026-10-18

> 本文定义用户可见的产品行为，不规定框架、组件库、存储结构、实现顺序或工期。实现 agent 不得用技术偏好改变本文的确认规则。

## 1. 产品定位

### 用户

同时维护大量工作项目、公司管理入口和技术资料链接，并频繁在本地、开发、测试、生产环境之间切换的 Chrome 用户。

### 问题

普通书签列表容易按环境或时间堆积，难以快速回答“这是哪个项目的哪个环境”；公司工具、工作项目和个人技术资料混在一起也会增加查找成本。

### 产品承诺

每次打开 Chrome 新标签页时，用户都能在一个完整的书签工作台中，先按用途切换分类，再按项目或主题找到分组，最后打开正确的链接。

### 与相邻方案的区别

- 不是 Chrome 原生书签的查看器或整理器。
- 不是跨设备书签同步服务。
- 不是自动抓取、推荐或分类网址的工具。
- MVP 是用户手动维护、保存在当前浏览器本地的一套链接工作台。

## 2. 核心场景

1. 新建标签页后，在“工作项目”中找到某个项目并打开其本地、开发、测试或生产环境。
2. 切换到“公司管理”，打开 GitHub、GitBucket、考勤等公司工具。
3. 切换到“技术兴趣”，打开 Phalcon、Laravel 等技术文档。
4. 新项目或新工具出现时，新增分类、分组或链接；不再使用时进行编辑或删除。

## 3. 核心价值闭环

```text
打开新标签页
  → 进入上次使用的分类
  → 切换分类
  → 定位项目/主题分组
  → 打开目标链接
  → 新增或维护内容
  → 下次打开新标签页继续使用已保存的结果
```

闭环成立的必要条件：新标签页入口稳定、分类和分组结构清楚、链接打开方式可预测、所有用户配置能在浏览器重启后保留。

## 5. 页面与信息结构

### 5.1 总体布局

页面占满新标签页可用区域，主体是一个完整工作台面板，不使用浏览器弹窗作为主要界面。

```text
┌──────────────────────────────────────────────────────────────────────┐
│ Bookmark Organizer                                      [管理内容]  │
│                                                                      │
│ [工作项目]  [公司管理]  [技术兴趣]  [+ 新增分类]                      │
├──────────────────────────────────────────────────────────────────────┤
│ 工作项目                                                 [+ 新增分组]│
│                                                                      │
│ ┌─ 项目 A ──────────────────┐  ┌─ 项目 B ──────────────────┐         │
│ │ [本地] [开发] [测试] [生产]│  │ [本地] [开发]       [生产]│         │
│ └───────────────────────────┘  └───────────────────────────┘         │
│                                                                      │
│ ┌─ 项目 C ──────────────────┐                                       │
│ │ [本地] [测试] [生产]       │                                       │
│ └───────────────────────────┘                                       │
└──────────────────────────────────────────────────────────────────────┘
```

布局规则：

- 顶部为产品标题、分类栏和进入管理状态的入口。
- 分类栏下只展示当前分类的内容，不把多个分类混在同一页面。
- 分组以清晰的卡片或区块呈现；宽屏可多列，小屏按单列顺序呈现。
- 缺少某个环境时不显示空占位符，例如没有测试环境就只显示实际存在的链接。
- 浏览状态强调快速打开链接；新增、编辑、删除操作集中在管理状态，避免默认页面充满维护按钮。

### 5.2 初始分类

首次使用自动创建三个空分类，顺序固定为：

1. `工作项目`：工作项目及其不同环境。
2. `公司管理`：GitHub、GitBucket、考勤等公司工具。
3. `技术兴趣`：Phalcon、Laravel 等技术文档或个人关注站点。

这些名称是默认值，不是保留字；用户之后可以重命名或删除。

### 5.3 通用内容模型

```text
分类
└── 分组（工作项目中通常代表一个项目，其他分类中代表一个主题）
    └── 链接
        ├── 显示名称
        ├── URL
        └── 可选标识（例如：本地 / 开发 / 测试 / 生产）
```

## 6. 已确认产品决策

| 决策 ID | 关联功能 | 确认规则 | 理由 |
| --- | --- | --- | --- |
| `DEC-001` | `NAV-HOME-001` | 扩展接管 Chrome 新标签页；浏览器启动时只有在 Chrome 本身打开新标签页的情况下才出现工作台。 | 不改写用户已有的启动页配置。 |
| `DEC-002` | `NAV-CAT-001` | 首次使用默认三个分类；以后打开新标签页时恢复最近一次使用的分类。 | 减少重复切换。 |
| `DEC-003` | `NAV-CAT-001` | 焦点位于分类栏时，`Tab` 前进并激活下一分类，`Shift+Tab` 后退并激活上一分类；到达分类栏边界后离开分类栏进入其他可操作内容，不形成键盘陷阱。 | 满足 Tab 键切换需求，同时保留键盘访问页面内容的能力。 |
| `DEC-004` | `NAV-CAT-002` | 至少保留一个分类；最后一个分类不可删除。 | 页面始终有有效容器。 |
| `DEC-005` | `ORG-GROUP-001` | 分组是所有分类共用的组织单位；在“工作项目”中默认理解为项目，在其他分类中可表示任意主题。 | 结构一致且不限制未来分类。 |
| `DEC-006` | `ORG-LINK-001` | 本地、开发、测试、生产是建议标识而非强制槽位；链接可缺少任意环境，也可使用自定义标识。 | 适配环境不完整和非项目类网址。 |
| `DEC-007` | `OPEN-LINK-001` | 普通点击在当前标签页打开；按住 Windows/Linux 的 `Ctrl` 或 macOS 的 `Command` 点击时在新的浏览器标签页打开。 | 保持跨平台且符合浏览器习惯。 |
| `DEC-008` | 全部 | 数据仅保存在当前 Chrome 浏览器本地，不做账号、云端或跨设备同步。 | 用户明确暂不做同步。 |
| `DEC-009` | 全部 | MVP 不读取、导入或修改 Chrome 原生书签。 | 当前价值是自定义新标签页工作台。 |

## 7. 功能规格

### 7.1 `NAV-HOME-001` 新标签页工作台

产品状态：`Ready for Delivery`  
当前可用性：`Not built`

#### 用户问题与价值

用户不希望每次先打开书签管理器或查找收藏夹；打开新标签页就应直接看到可操作的链接工作台。

#### 用户与触发

已启用扩展的用户新建 Chrome 标签页，或以“打开新标签页”作为启动行为打开浏览器。

#### 包含

- 用书签工作台替代默认新标签页内容。
- 显示完整页面面板、分类栏和当前分类内容。
- 首次使用创建三个默认空分类。
- 非首次使用恢复本地保存的数据与最近使用分类。

#### 不包含

- 修改已配置为特定网址的 Chrome 启动页。
- 接管主页按钮或普通网页。
- 原生书签导入、搜索、推荐、同步。

#### 前置条件

扩展已安装、启用，并被允许作为新标签页页面运行。

#### 主流程

1. 用户新建标签页。
2. 工作台直接出现。
3. 工作台显示最近使用的分类及其分组、链接。
4. 用户继续切换分类或打开链接。

#### 状态与例外

- 首次使用：显示三个默认分类，并在内容区显示引导新增第一个分组的空状态。
- 当前分类为空：显示分类名称、用途说明和“新增分组”入口，不显示伪造示例数据。
- 本地数据无法读取：显示非破坏性错误状态和“重试”，不得自动清空或覆盖已有数据。

#### 业务规则与默认值

- 初始激活分类为“工作项目”。
- 用户成功切换分类后，新的激活分类成为下次打开新标签页的默认分类。
- 工作台必须适应常见桌面宽度；内容超出一屏时页面可纵向滚动。

#### 关系

承载 `NAV-CAT-001`、`NAV-CAT-002`、`ORG-GROUP-001`、`ORG-LINK-001` 和 `OPEN-LINK-001`。

#### 用户可见信息与操作

产品标题、分类、当前分类名称、分组、链接、管理入口、空状态或错误状态。

#### 数据概念

首次使用标记、最近使用分类、用户创建的分类/分组/链接集合。

#### 可靠性与来源

页面只展示用户保存的数据，不自动生成真实项目或链接。

#### 用例

- 正常：用户按快捷键新建标签页，直接看到上次打开的“公司管理”。
- 边界：浏览器本地数据暂时无法读取，页面展示重试且不生成一套新数据覆盖旧内容。

#### 验收标准

- 新建 Chrome 标签页时出现 Bookmark Organizer，而不是 Chrome 默认页。
- 首次使用能看到三个默认分类与明确空状态。
- 浏览器重启后，已保存内容和最近使用分类仍然存在。
- 工作台内容超过一屏时仍可访问全部分组。
- 数据读取失败时有可理解的恢复入口且不丢失数据。

#### 开放决策

无阻塞决策。

### 7.2 `NAV-CAT-001` 分类切换

产品状态：`Ready for Delivery`  
当前可用性：`Not built`

#### 用户问题与价值

用户需要把工作项目、公司工具与个人技术资料隔离，快速缩小查找范围。

#### 用户与触发

用户在工作台点击分类，或用键盘在分类栏中切换。

#### 包含

- 单击分类立即激活并展示其内容。
- 键盘 `Tab`、`Shift+Tab` 在分类栏内依次切换并激活分类。
- 左右方向键也可在分类栏内循环切换，作为标准键盘补充行为。
- 清楚标识当前激活分类与键盘焦点。

#### 不包含

- 同时并排显示多个分类。
- 分类内容的全局搜索或跨分类聚合。

#### 前置条件

至少存在一个分类。

#### 主流程

1. 用户将焦点置于分类栏或点击某分类。
2. 目标分类成为激活分类。
3. 内容区替换为目标分类的分组与链接。
4. 激活分类被保存为最近使用分类。

#### 状态与例外

- 目标分类为空：正常切换，并显示该分类空状态。
- 分类数量超出可用宽度：分类栏可水平滚动，当前分类始终可见。
- 管理对话框打开时：`Tab` 用于对话框内的标准焦点移动，不触发分类切换。

#### 业务规则与默认值

- 任一时刻只能激活一个分类。
- 分类栏获得初始焦点时，从当前激活分类开始。
- 在分类栏最后一个分类按 `Tab` 时进入页面下一个可操作区域；在第一个分类按 `Shift+Tab` 时移出分类栏。
- 在分类栏内使用左右方向键时允许首尾循环。

#### 关系

切换 `NAV-HOME-001` 当前显示的分类，并决定 `ORG-GROUP-001` 展示的数据范围。

#### 用户可见信息与操作

分类名称、激活状态、焦点状态、点击与键盘切换。

#### 数据概念

分类顺序、当前激活分类、最近使用分类。

#### 可靠性与来源

分类名称与顺序来自用户保存的数据；系统只在首次使用创建默认分类。

#### 用例

- 正常：焦点在“工作项目”，用户按一次 `Tab`，立即切换到“公司管理”。
- 边界：用户拥有很多分类，目标分类在可视范围外；键盘切换后分类栏自动滚动使其可见。

#### 验收标准

- 点击任一分类后只显示该分类内容。
- 焦点位于分类栏时，`Tab` 和 `Shift+Tab` 按确认规则切换分类。
- 左右方向键能循环切换分类。
- 离开分类栏后，`Tab` 恢复为页面正常焦点导航。
- 当前分类在视觉上不能只依赖颜色区分。

#### 开放决策

无阻塞决策。

### 7.3 `NAV-CAT-002` 分类管理

产品状态：`Ready for Delivery`  
当前可用性：`Not built`

#### 用户问题与价值

三个默认分类不能覆盖未来全部用途，用户需要维护自己的分类结构。

#### 用户与触发

用户进入管理状态，并选择新增、重命名或删除分类。

#### 包含

- 新增分类并填写名称。
- 重命名已有分类。
- 删除分类。
- 查看删除确认中包含的分组与链接数量。

#### 不包含

- 分类排序或拖拽重排。
- 分类模板、共享、导入或导出。

#### 前置条件

工作台已加载；删除时分类总数必须大于一。

#### 主流程

1. 用户进入管理状态。
2. 选择“新增分类”。
3. 输入非空名称并保存。
4. 新分类出现在分类栏并成为当前分类。

#### 状态与例外

- 空名称或仅空格：不可保存，并提示名称必填。
- 同名分类：允许保存；分类通过位置和内容区分，不强制唯一。
- 删除非空分类：确认信息必须显示将删除的分组数和链接数。
- 删除当前分类：删除后激活其左侧分类；若没有左侧分类则激活右侧分类。
- 只剩一个分类：不提供删除完成动作，并解释至少需保留一个分类。

#### 业务规则与默认值

- 名称保存时移除首尾空格。
- 新分类追加到分类栏末尾。
- 删除分类会连同其中所有分组和链接一起删除，必须在最终确认前说明影响。
- 取消新增、编辑或删除不得改变已有数据。

#### 关系

创建和维护 `NAV-CAT-001` 的导航项，并作为 `ORG-GROUP-001` 的上级容器。

#### 用户可见信息与操作

分类名称输入、保存、取消、重命名、删除、删除影响摘要。

#### 数据概念

分类名称、创建顺序、包含的分组与链接数量。

#### 可靠性与来源

所有分类变更均由用户明确操作产生，不做自动分类。

#### 用例

- 正常：用户新增“个人生活”，保存后立即切换到新分类的空状态。
- 边界：用户尝试删除唯一剩余分类，系统阻止删除并说明原因。

#### 验收标准

- 用户可以新增和重命名分类，刷新或重启后结果仍存在。
- 非空名称校验明确且不丢失用户已输入内容。
- 删除非空分类前能看到受影响的分组和链接数量。
- 取消删除后分类及内容保持不变。
- 最后一个分类不能被删除。

#### 开放决策

无阻塞决策。

### 7.4 `ORG-GROUP-001` 分组管理

产品状态：`Ready for Delivery`  
当前可用性：`Not built`

#### 用户问题与价值

按环境类型平铺链接会让同一项目散落各处；分组必须优先表达“属于哪个项目或主题”。

#### 用户与触发

用户在当前分类中新增、重命名或删除分组。

#### 包含

- 在当前分类新增命名分组。
- 重命名分组。
- 删除分组及其链接。
- 分组在浏览状态中作为独立视觉区块展示。

#### 不包含

- 分组跨分类移动、复制或排序。
- 嵌套分组。
- 根据域名或环境自动分组。

#### 前置条件

存在当前分类。

#### 主流程

1. 用户在当前分类选择“新增分组”。
2. 输入项目或主题名称并保存。
3. 新分组追加到当前分类末尾。
4. 用户可继续向该分组添加链接。

#### 状态与例外

- 当前分类无分组：显示引导性空状态。
- 空名称或仅空格：不可保存。
- 同名分组：允许，避免对真实项目命名施加不必要限制。
- 删除含链接的分组：确认信息必须显示链接数量。

#### 业务规则与默认值

- 名称保存时移除首尾空格。
- 新分组追加到当前分类末尾。
- 缺少某些环境链接时不展示空槽位或“暂无”占位。
- 删除分组会删除其中链接，必须确认；取消不改变数据。

#### 关系

属于 `NAV-CAT-002` 管理的分类，并作为 `ORG-LINK-001` 的上级容器。

#### 用户可见信息与操作

分组名称、其中的链接数量、添加链接、重命名、删除及确认。

#### 数据概念

分组名称、所属分类、创建顺序、包含的链接。

#### 可靠性与来源

分组完全由用户维护，不根据网址自动推断项目。

#### 用例

### 7.7 `DATA-IMPORT-001` 结构化文件导入

#### 数据安全不可变更原则（10项铁律）

1. **追加或合并优先**：导入操作仅允许新增不存在的对象，或对同名容器进行向下合并。绝对禁止整体覆盖用户现有工作区。
2. **已有未提及对象保持不变**：导入文件中不存在的分类、分组与链接完全保留，不受任何干扰。
3. **零删除原则**：导入过程绝不执行任何物理删除或逻辑删除操作。
4. **禁止危险入口**：UI 坚决不提供“全量覆盖导入”、“清空后导入”等不可逆破坏性入口。
5. **原子回滚与零写入**：格式校验不通过、事务中断、存储满载或写入失败时，现有数据保持原样，做到零污染。
6. **强制预导入快照**：每次执行实际写入前，系统自动在本地 IndexedDB 创建全量快照（包含当前全量分类、分组与链接）。
7. **一键撤销本次导入**：导入完成后常驻撤销入口，用户可一键精准回滚本次导入批次，恢复至导入前状态。
8. **标准化 JSON 全量备份导出**：提供一键导出完整工作台 JSON 备份功能，导出的备份文件可无损完整重新导入。
9. **透明显式冲突处理**：完全相同的对象跳过；同 URL 但标题/标签不同的记录标记为冲突，必须由用户在预览面板中抉择（“保留已有”或“同时保留”），绝不静默覆盖。
10. **纯客户端本地隔离**：所有哈希计算（SHA-256）、校验与存储均在本地完成，无任何网络依赖与外部数据泄露。

#### 导入与导出 JSON Schema 规范 (`formatVersion: 1`)

采用**扁平三顶层数组结构**（`categories`、`groups`、`links`），通过 `categoryId` 与 `groupId` 建立显式引用关系，与 IndexedDB 表结构及备份导出格式严格对齐。禁止使用嵌套的 `categories[].groups[].links[]` 结构（校验器会显式报错拦截，杜绝静默忽略）：

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "title": "PowerLessToy Bookmark Organizer Import/Export Format",
  "type": "object",
  "required": ["formatVersion", "categories", "groups", "links"],
  "properties": {
    "formatVersion": { "type": "integer", "enum": [1] },
    "exportedAt": { "type": "string", "format": "date-time" },
    "categories": {
      "type": "array",
      "items": {
        "type": "object",
        "required": ["id", "name"],
        "properties": {
          "id": { "type": "string", "minLength": 1 },
          "name": { "type": "string", "minLength": 1 },
          "description": { "type": "string" },
          "revision": { "type": "integer", "minimum": 1 },
          "createdAt": { "type": "string" },
          "updatedAt": { "type": "string" }
        }
      }
    },
    "groups": {
      "type": "array",
      "items": {
        "type": "object",
        "required": ["id", "categoryId", "name"],
        "properties": {
          "id": { "type": "string", "minLength": 1 },
          "categoryId": { "type": "string", "minLength": 1 },
          "name": { "type": "string", "minLength": 1 },
          "revision": { "type": "integer", "minimum": 1 },
          "createdAt": { "type": "string" },
          "updatedAt": { "type": "string" }
        }
      }
    },
    "links": {
      "type": "array",
      "items": {
        "type": "object",
        "required": ["groupId", "name", "url"],
        "properties": {
          "id": { "type": "string", "minLength": 1 },
          "groupId": { "type": "string", "minLength": 1 },
          "name": { "type": "string", "minLength": 1 },
          "url": { "type": "string", "format": "uri" },
          "badge": { "type": "string" },
          "revision": { "type": "integer", "minimum": 1 },
          "createdAt": { "type": "string" },
          "updatedAt": { "type": "string" }
        }
      }
    }
  }
}
```

校验器同时执行**引用完整性校验**：
- `categories` 与 `groups` 的 `id` 必须非空且在各自数组内唯一；`links` 若提供 `id` 也必须唯一。
- 每个 `group.categoryId` 必须指向同一导入文件中的某个 `category.id`。
- 每个 `link.groupId` 必须指向同一导入文件中的某个 `group.id`。
- 缺失 `id` 的链接使用稳定的数组下标键（`links[i]`）标识冲突策略，确保“同时保留（Keep both）”策略在预览与执行阶段完全一致。

#### 撤销导入安全保护与快照恢复

当用户点击“撤销本次导入”时，系统在事务前执行所有权与变更检查（`analyzeUndo`）：
- 检查本次导入创建的分类、分组、链接的 `revision` 是否仍为 `1`（未被用户后续编辑）。
- 检查本次导入创建的分类或分组下是否包含非本次导入新增的子分组或子链接（防止删父留子产生孤儿记录）。
- 若存在后续修改或新增子项，直接阻断自动批次删除（返回 `UNDO_BLOCKED`），并在弹窗中明确展示受影响数量，提供**从导入前快照恢复（`restoreSnapshot`）**的显式选项及会回滚的后续变更统计。

#### 并发控制与乐观锁模型

所有业务实体（Category、Group、Link）均具备 `revision` 字段（从 1 递增）。当执行更新（重命名分类/分组、编辑链接）时，必须携带页面加载时持有的 `expectedRevision`：
- 若数据库中的 `latest.revision === expectedRevision`，则允许写入，将 `revision` 递增 1 并刷新 `updatedAt`。
- 若不相等，直接抛出 `CONFLICT` 异常，拒绝修改，并在 UI 提示用户数据已在其他标签页被修改，引导用户刷新页面，防止旧快照静默覆盖新状态。

#### 存储引擎与多标签页协同架构

1. **主存储引擎**：迁移至浏览器原生 **IndexedDB**（数据库：`powerless_toy_bookmarks_db`），包含 6 个核心存储区：
   - `categories`：分类表，包含 `id`, `name`, `description`, `revision`, `createdAt`, `updatedAt`。
   - `groups`：分组表，包含 `id`, `categoryId`, `name`, `revision`, `createdAt`, `updatedAt`。
   - `links`：链接表，包含 `id`, `groupId`, `name`, `url`, `badge`, `revision`, `createdAt`, `updatedAt`。
   - `importJobs`：导入作业批次审计表，记录文件哈希、新增 ID、导入时间与关联快照。
   - `snapshots`：快照表，保存导入前及重要变更前的完整数据快照。
   - `metadata`：元数据表，权威记录架构版本与持久化迁移状态（`key: "migration"`）。只要 IndexedDB 中已存在任何业务记录，即使 `chrome.storage.local` 中的轻量迁移标记丢失，也绝不清空或覆盖 IndexedDB，而是自动对账补全迁移状态；旧存储若存在损坏的非数组或非法记录，立即以 `CORRUPTED_LEGACY_DATA` 阻断迁移并保留现场。
2. **轻量偏好存储**：`chrome.storage.local` 仅用于当前激活分类 (`powerless_toy_active_category_v1`) 与界面偏好。
3. **跨标签页实时同步**：所有已提交的 IndexedDB 读写事务通过 `BroadcastChannel("powerless_toy_bookmark_organizer_db_v1")` 广播变更通知，结合 `chrome.storage.onChanged` 与 `window.storage` 事件，实现多标签页并发编辑、导入、撤销的实时刷新；导出与导入预览始终从 IndexedDB 直接读取最新状态。

| 首次使用 | 创建三个默认空分类，激活“工作项目”，引导新增分组。 |
| 分类为空 | 保留分类导航，显示该分类用途与“新增分组”。 |
| 分组为空 | 显示分组名称与“新增链接”，不显示环境空槽。 |
| 浏览状态 | 突出分类、分组和链接；维护操作收起。 |
| 管理状态 | 显示新增、编辑、删除入口；链接仍可识别，但维护控件不触发导航。 |
| 表单校验失败 | 保留用户输入，在相关字段旁说明错误。 |
| 删除确认 | 显示对象名称以及会连带删除的内容数量。 |
| 数据读取失败 | 不生成覆盖数据；显示错误与重试。 |
| 数据保存失败 | 保留当前编辑内容并允许重试或取消，不把失败显示为成功。 |

## 9. MVP 范围外

| 项目 | 产品状态 | 原因 |
| --- | --- | --- |
| 账号、云端或跨设备同步 | Deferred | 用户明确暂不做同步。 |
| Chrome 原生书签读取、导入、修改 | Rejected for MVP | 当前产品是独立的新标签页链接工作台。 |
| 搜索与过滤 | Deferred | 有价值，但当前需求未要求。 |
| 分类、分组、链接拖拽排序 | Deferred | MVP 使用创建顺序，减少未确认交互。 |
| 自动抓取标题、图标、描述 | Deferred | 避免网络与隐私范围扩张。 |
| 链接健康检查和访问统计 | Deferred | 不属于当前快速访问闭环。 |
| 结构化文件导入 | Delivered | 已交付完整实现，满足 10 项数据安全不可变更原则。 |
| 数据导出和备份 | Delivered | 已交付标准全量 JSON 备份导出与再导入验证能力。 |
| 团队共享与权限 | Deferred | MVP 是单用户本地工具。 |

实现 agent 不得因为“常见书签产品通常会有”而把这些内容加入 MVP。

## 10. 产品关系与覆盖检查

### 关系

- `NAV-HOME-001` 提供其他功能的统一入口。
- `NAV-CAT-002` 产生分类，供 `NAV-CAT-001` 切换。
- `ORG-GROUP-001` 消费当前分类，并为 `ORG-LINK-001` 提供容器。
- `ORG-LINK-001` 产生可访问 URL，供 `OPEN-LINK-001` 打开。
- `DATA-IMPORT-001` 批量导入分类、分组和链接，具备预导入快照与撤销能力。
- 本地持久化贯穿所有管理功能，是下一次新标签页恢复工作台的前提。

### 覆盖检查

- 入口 → 分类 → 分组 → 链接 → 打开的核心闭环完整。
- 新增、编辑、删除、空状态、失败状态和恢复行为均有定义。
- “Tab 键切换分类”和页面键盘可访问性之间的冲突已通过分类栏边界规则解决。
- 项目缺少某些环境时的行为已定义为不显示空槽位。
- 同步、原生书签和自动化能力已明确排除，不存在隐性依赖。
- 结构化导入与备份导出已落地为安全合并、冲突预览、原子事务与一键撤销机制。

## 11. 交付给实现 agent 的不可变约束

以下规则已经确认，除非用户更新本文，否则实现不得自行改变：

1. 新标签页是产品主入口，主界面是完整页面而非弹窗。
2. 首次使用必须有“工作项目、公司管理、技术兴趣”三个空分类。
3. 分类、分组和链接均由用户管理；至少保留一个分类。
4. 分组优先表达项目或主题，环境只是链接的可选标识。
5. 本地、开发、测试、生产不是强制齐全的固定槽位。
6. 普通点击当前页打开，`Ctrl/Command+点击`新标签页打开。
7. 用户配置必须在刷新和浏览器重启后保留。
8. 只做当前浏览器本地数据，不做同步，不读取 Chrome 原生书签。
9. MVP 不增加本文“范围外”表格中的能力。
10. `DATA-IMPORT-001` 已达到 `Delivered`；导入严格遵循 JSON `formatVersion: 1` 规范与 10 项数据安全原则。

## 12. 整体产品验收

当且仅当以下场景全部成立，MVP 才满足本产品定义：

1. 全新安装后打开新标签页，出现三个默认分类和空状态。
2. 用户能新增“订单系统”分组，只添加本地、测试、生产三个链接，而无需创建开发环境空位。
3. 用户能在分类栏用点击、`Tab`、`Shift+Tab` 和方向键切换分类，并能继续用键盘进入内容。
4. 用户能新增、重命名、删除分类和分组，危险删除前能看到影响范围并取消。
5. 用户能新增、编辑、删除带可选环境标识的链接，校验失败时输入不丢失。
6. 普通点击替换当前标签页；`Ctrl/Command+点击`保留工作台并打开新标签页。
7. 刷新页面和重启浏览器后，内容与最近使用分类保持一致。
8. 用户能安全导入 `formatVersion: 1` 的 JSON 文件，导入前可预览数量与冲突；支持一键撤销本次导入与导出备份。
9. MVP 中不存在同步、Chrome 原生书签导入、搜索、自动抓取、访问统计等未授权扩展入口。
