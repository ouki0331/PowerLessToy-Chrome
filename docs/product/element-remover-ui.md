# Element Remover UI/UX 设计指引

文档状态：实现约束<br>
适用界面：扩展面板、页面选择覆盖层、Debug 标记、规则设置页<br>
设计模式：`Operate`<br>
产品事实来源：[`element-remover.md`](element-remover.md)<br>
设计方法：Impeccable 4.3.1

> 本文定义实现 agent 必须遵守的界面层级、交互反馈和可访问性要求，不包含业务代码。产品行为与本文冲突时，以产品规格为准。

## 1. 设计方向：Quiet Inspector

Element Remover 应像一个精确、克制、可信赖的网页检查工具，而不是高存在感的广告拦截仪表盘。

- 页面覆盖层必须服务选取，不用装饰争夺注意力。
- 扩展面板优先回答“当前页面发生了什么”和“下一步能做什么”。
- 设置页支持大量规则的扫描和恢复，不把所有信息塞进小弹窗。
- 色彩策略为冷静中性色加单一蓝紫强调色；危险删除使用克制的错误色。
- 使用系统无衬线字体与统一图标体系，不用 emoji 作为正式图标。
- 状态必须有文字，不以颜色或图标单独表达。

## 2. 界面分工

### 扩展面板：当前页面快速控制

```text
┌────────────────────────────────────┐
│ Element Remover             [设置] │
│ example.com · /article/*           │
│                                    │
│ 已处理 7 个                        │
│ 5 个已移除 · 2 个已隐藏            │
│                                    │
│ [选择页面元素]                     │
│ Debug 标记                  [关闭] │
├────────────────────────────────────┤
│ 当前页面规则                       │
│ 侧栏广告      移除 · 1 个   [恢复] │
│ 推荐内容      隐藏 · 6 个   [恢复] │
│                                    │
│ [管理全部规则]                     │
└────────────────────────────────────┘
```

- 面板是快速操作面，不承载复杂批量编辑。
- “选择页面元素”是唯一主要操作。
- 当前页面摘要先于规则详情。
- Debug 是明确的临时模式开关，并说明开启后可能需要刷新。
- 规则多时列表在面板内部滚动，顶部摘要和主要操作保持可见。

### 页面选择覆盖层：批量选取

```text
网页内容
  ┌─ 候选元素边界 ─────────────────┐
  │                                │
  └────────────────────────────────┘

┌──────────────────────────────────────────────┐
│ 已选择 3 个   默认：移除                     │
│ [查看列表]                    [取消] [预览]  │
└──────────────────────────────────────────────┘
```

- 工具条固定在不易遮挡内容的边缘，并允许在必要时换边。
- 候选高亮、已选择高亮和 Debug 标记使用不同形态，避免混淆。
- 已选择目标显示稳定编号，与待处理列表一一对应。
- 单击加入或取消目标后只给出短促状态反馈，不弹出阻断式对话框。
- 页面原有交互在选择模式中暂停，退出后完整恢复。

### 设置页：全部规则管理

设置页使用“主机名 → 路径 → 规则”的渐进层级。默认先显示网站摘要，展开后查看路径和规则；不把全部选择器一次铺满。

- 主机名行显示启用规则数、暂停数和需要复核数。
- 路径行显示明确的匹配范围，不隐藏通配符。
- 规则行显示人类可读名称、处理方式、可靠性状态和最后命中状态。
- 高级选择器信息默认折叠，普通恢复流程不依赖它。
- 批量恢复是常规操作；批量删除是危险操作，必须视觉降级并确认影响数量。

## 3. 选择状态与反馈

### 候选状态

- 使用清晰但不过度发光的边界和轻微遮罩。
- 候选元素必须与其父级边界容易区分。
- 显示简短标签，例如 `aside · 推荐内容`，但不能覆盖目标主要内容。
- 极小元素的高亮区域可以设置最低可见尺寸，但不能改变实际选择目标。

### 已选择状态

- 使用编号标记和持续边界，不能只改变颜色。
- 再次点击取消时编号重新整理，但待处理列表应保持稳定、可理解。
- 父子目标同时存在时，在列表中显示包含关系提示。

### 预览状态

- 预览应在真实页面上呈现全部移除/隐藏结果。
- 工具条显示本次目标总数、移除数、隐藏数和失效数。
- 用户可以退出预览继续选择，不丢失当前批次。
- 保存前显示作用范围，并把自动泛化的路径片段突出为可检查文本。

## 4. 移除与隐藏控件

- 使用带文字的二选一控件：“移除”“隐藏”。
- 默认选中“移除”，但不能用危险红色表示；移除是正常功能，不是错误。
- 每个目标继承批次默认值，用户可以逐项修改。
- “删除规则”才使用危险语义，不要把它与“移除网页元素”混为一套红色警告。
- 帮助说明用一句话解释差异：移除更彻底；隐藏保留页面节点，兼容性通常更好。

## 5. Debug 标记与恢复浮层

### 标记

- 使用小型蓝紫色空心菱形或定位点，不使用 emoji、红色叉号或高亮荧光。
- 标记默认低对比，处于独立覆盖层，不占页面布局。
- 多个标记重叠时聚合为数量标记。
- 收起标记不应阻挡底层网页；获得指针意图、点击或键盘焦点后才展开交互。

### 恢复浮层

```text
┌────────────────────────────┐
│ 侧栏广告                   │
│ 已移除 · 规则 #04 · 精确   │
│                            │
│ [恢复并停用规则]           │
│ 仅本次显示此元素           │
└────────────────────────────┘
```

- 悬停、点击和 `focus-visible` 都能打开浮层；关键操作不能只在 hover 时可用。
- 主操作为“恢复并停用规则”。
- 多实例规则在按钮附近显示“将恢复 N 个元素”。
- 次级操作“仅本次显示此元素”只在有明确单实例意义时出现。
- `Enter` 执行当前主操作，`Esc` 关闭浮层并把焦点返回标记。
- 浮层使用顶层定位，不能被网页的 `overflow`、层叠上下文或裁剪区域截断。

### 刷新回退

无法原位恢复时，使用紧凑确认界面说明：

- 对应规则已停用。
- 需要刷新才能恢复元素。
- 将尽量回到原浏览位置。
- 未提交的表单内容可能丢失。

主要操作为“刷新并恢复”，取消操作为“暂不刷新”。不得在用户未确认时刷新。

## 6. 规则状态语言

| 状态 | 含义 | 界面要求 |
| --- | --- | --- |
| 精确 | 当前结果符合预期且唯一 | 使用中性成功状态与文字 |
| 可能变化 | 使用了较弱或动态特征 | 提供查看范围或重新选择入口 |
| 需要复核 | 匹配数量异常或存在歧义 | 暂停执行并突出复核操作 |
| 当前未匹配 | 当前页面暂时没有目标 | 保留规则，不使用错误语气 |
| 已停用 | 用户恢复后保留的规则 | 降低视觉权重并提供重新启用 |

错误色只用于真正失败或永久删除确认。“当前未匹配”不是错误。

## 7. 角标与状态一致性

- 浏览器角标与面板摘要必须使用同一计数口径。
- 角标为零时隐藏，不使用 `0` 制造噪音。
- 面板摘要同时给出移除与隐藏的拆分数量。
- Debug 恢复后，标记、规则状态、摘要和角标应一起更新，不能出现彼此矛盾的状态。
- 状态更新使用克制的就地反馈，不用全屏成功动画或连续跳动角标。

## 8. 设置页密度与压力范围

设计至少验证以下数据范围：

| 内容 | 最小 | 典型 | 压力范围 |
| --- | ---: | ---: | ---: |
| 已管理网站 | 0 | 10–30 | 200 |
| 单网站路径范围 | 1 | 3–10 | 50 |
| 单路径规则 | 1 | 5–20 | 100 |
| 当前页面命中实例 | 0 | 1–20 | 100+ |
| 主机名或路径长度 | 短 | 30–80 字符 | 200 字符 |

- 长路径使用中段省略并提供完整可访问文本，不能只保留开头而看不到关键末段。
- 大量网站下仍需快速定位异常规则；允许设置页提供本地搜索和状态筛选，但它们不改变规则业务含义。
- 不为每条规则制造大卡片；优先使用紧凑行、分组和渐进展开。
- 不允许页面级横向滚动。

## 9. 空、失败与权限状态

### 首次使用

面板显示简短说明和唯一主要操作“选择页面元素”，不展示伪造规则。

### 当前页面无规则

显示“此页面还没有清理规则”，并保留选择入口。角标为空。

### 设置页为空

解释规则会在用户第一次保存页面元素后出现在这里，并提供返回当前网页开始选择的指引。

### 读取或保存失败

- 保留用户当前选择和调整。
- 明确指出尚未保存或尚未读取。
- 提供重试，不自动清空本地规则。

### 不支持或无权限

- Chrome 内部页面、扩展商店、部分内置页面或受限框架显示明确原因。
- 操作按钮进入不可用状态并配合文字说明，不能只显示灰色按钮。

## 10. 可访问性与键盘

- 选择工具条、待处理列表、预览、Debug 标记和设置页均可通过键盘访问。
- 焦点状态与选中状态使用不同表达。
- 所有图标按钮都有可访问名称和可见提示。
- Debug 标记即使视觉很小，也应提供足够的键盘焦点目标；不能要求精确鼠标操作。
- 页面缩放至 200% 时，扩展面板和设置页不丢失操作。
- 状态变化通过适当的可访问通知传达，但动态匹配不能频繁打断屏幕阅读器。
- 支持系统减少动态效果设置。

## 11. 动效

- 常规状态过渡目标为 150–250ms。
- 动效只解释候选、选中、预览、恢复和展开状态。
- 不做页面加载动画、标记脉冲循环、霓虹闪烁或卡片依次飞入。
- Debug 标记出现不能造成页面布局移动。
- 恢复浏览位置后的校正应平稳但短暂；减少动态效果时直接定位。

## 12. 明确禁止

- 关键恢复操作只在 hover 时出现。
- 用红色表示正常的“移除元素”。
- 大面积渐变、玻璃拟态、霓虹发光或动画扫描线。
- 用 emoji 作为选择、恢复、调试或设置图标。
- 每条规则使用不同随机颜色。
- 把完整 CSS Selector 作为普通用户的主要标签。
- 在小弹窗中堆叠全部网站规则和复杂批量编辑。
- 静默刷新或无提示丢弃未保存选择。
- 依靠颜色单独表达精确、异常、停用或焦点状态。

## 13. 实现与审查交接

实现 agent 必须：

1. 先阅读产品规格和本文，不得只依据 README 摘要实现。
2. 在实现 UI 时使用已安装的 Impeccable 技能，并按 `Operate` 模式执行。
3. 使用真实网页结构验证普通 DOM、动态列表、长路径、重复内容和多目标批次。
4. 检查扩展面板、页面覆盖层、预览、Debug、刷新确认和设置页。
5. 提供选择前、批量选择、Debug 恢复、设置页典型数据与压力数据截图。
6. 验证鼠标、键盘、200% 缩放、减少动态效果和不支持页面状态。

代码审查至少检查：

- 面板是否立即说明当前页面处理数量与主要操作。
- 连续选择是否避免每个元素都打开一次阻断式流程。
- 候选、已选择与 Debug 标记是否容易区分。
- 恢复是否可见、可聚焦，并与永久删除明确分离。
- 刷新恢复是否提示风险并尽量回到原浏览位置。
- 大量规则下设置页是否仍可扫描且没有横向溢出。
- 所有状态是否同时有文字与非颜色线索。
