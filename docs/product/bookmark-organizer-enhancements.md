# Bookmark Organizer 视觉增强与跨浏览器规格

文档状态：产品规格（Source of Truth 的扩展文档）<br>
产品事实来源：[`bookmark-organizer.md`](bookmark-organizer.md)<br>
界面约束来源：[`bookmark-organizer-ui.md`](bookmark-organizer-ui.md)<br>
最后更新：2026-10-23

> 本文定义链接展开、主题切换和 Firefox 桌面支持的用户可见行为。实现 agent 不得把浏览器兼容差异、图标获取失败或定位权限拒绝转化为数据丢失、页面不可用或静默降级。

## 1. 已确认方向

1. 保留当前分组排列与紧凑列表，不重做整体信息架构。
2. 默认仍以紧凑链接行呈现；需要更多信息时由用户主动展开。
3. 提供明确的浅色主题选择，同时保留深色、跟随系统和日出日落自动模式。
4. Firefox 桌面版需要成为正式支持平台；当前实现仅为部分兼容，不能标记为已支持。
5. 所有增强均不得改变现有分类、分组、链接、导入与备份的数据安全规则。

## 2. `VIEW-LINK-001` 可展开链接详情

产品状态：`Ready for Delivery`<br>
当前可用性：`Not built`

### 用户问题与价值

大量链接同时显示时，当前列表足够清楚但信息密度较高；用户需要在不牺牲快速扫描的前提下，按需查看网站图标、域名和完整地址，从而更有把握地识别目标网站。

### 用户与触发

用户在任意分组中看到链接，并点击链接行旁独立的展开控件，或用键盘聚焦后按 `Enter` / `Space`。

### 包含

- 每条链接提供与“打开链接”分离的展开／收起控件。
- 默认收起时保持现有紧凑列表，只显示链接名称与已有环境／自定义标识。
- 展开后显示网站图标、主机名、完整 URL 和已有标识；长 URL 可以换行或安全截断，但必须有查看完整值的可访问方式。
- 图标不可用时显示稳定的域名首字母占位，不显示破图、空白或无限加载状态。
- 同一分组内最多展开一条链接；展开另一条时自动收起前一条。不同分组可以各自展开一条。
- 展开状态只保留在当前页面会话中；新建另一个标签页时默认全部收起。

### 不包含

- 网页内容预览、截图、摘要、元数据抓取、访问次数或可用性检测。
- 在详情区重复放置编辑、删除等管理操作。
- 自动改写用户保存的链接名称、URL 或标识。
- 依赖第三方 favicon 聚合服务；不得为了图标把整份书签清单发送给第三方。

### 主流程

1. 用户打开新标签页，链接列表保持紧凑。
2. 用户激活某条链接的展开控件。
3. 当前链接行在原位置展开，显示图标、域名、完整 URL 与标识。
4. 用户可再次激活控件收起，或直接点击链接名称打开网站。

### 状态与例外

- 图标加载中：使用尺寸固定的占位，避免列表跳动。
- 图标失败、网站没有图标或浏览器不允许读取：改用域名首字母占位，其他详情仍正常显示。
- URL 很长：不得撑出分组卡片或产生页面级横向滚动。
- 链接处于管理状态：展开控件仍可识别，但不得与编辑／删除控件重叠或误触发导航。
- 浏览器离线：已有链接详情正常显示；图标失败按占位规则处理。

### 业务规则与默认值

- 链接名称仍是主要打开目标；展开控件必须具有单独点击区域和明确的“查看详情／收起详情”名称。
- 展开详情不会改变链接打开规则：普通点击当前页打开，修饰键点击在新标签页打开。
- 图标属于辅助识别信息，不得成为识别链接的唯一方式。
- 图标获取遵循按需与最少请求原则；只在用户展开时处理，不因打开新标签页而批量请求全部网站。

### 可靠性与来源

名称、URL 与标识来自用户保存的数据。网站图标来自目标站点或浏览器可提供的本地信息，可能缺失或过期，因此只能作为辅助信息；占位图标由本地根据域名生成。

### 用例

- 正常：用户展开“Cloudflare”，看到网站图标、`dash.cloudflare.com` 和完整 URL，确认后点击标题打开。
- 边界：某内网站点没有可访问图标且 URL 很长；详情使用域名首字母占位，URL 在卡片内安全换行，仍可正常打开。

### 验收标准

- 初始页面的信息密度不高于现有版本，所有链接默认收起。
- 展开和链接导航是两个独立操作，不会因查看详情而离开页面。
- 鼠标与键盘都能展开、收起并识别当前状态；控件暴露正确的展开状态。
- 同组只展开一条，切换展开对象时布局变化稳定且不丢失键盘焦点。
- 图标失败不会影响链接文字、URL、标识或打开行为。
- 100 个分组、每组 12 条链接的压力数据下，默认状态仍可快速扫描。

## 3. `VIEW-THEME-001` 手动与系统主题

产品状态：`Ready for Delivery`<br>
当前可用性：`Partial`（现有版本仅跟随系统深浅色）

### 用户问题与价值

用户在公司与家中面临不同光照环境，不能只由系统深色设置决定工作台外观；需要随时切换到更明亮的主题，并让选择在下次打开新标签页时保持一致。

### 包含

- 顶部提供可发现但不过度抢眼的主题入口。
- 提供四种选项：`浅色`、`深色`、`跟随系统`、`日出日落自动切换`。
- `浅色`与`深色`立即生效；`跟随系统`实时响应操作系统主题变化。
- 用户选择跨新标签页和浏览器重启保留。
- 首次使用与现有用户升级后的默认值为`跟随系统`，避免未经选择改变当前体验。

### 不包含

- 自定义配色器、主题商城、背景照片、动态壁纸或随机主题。
- 为每个分类设置独立主题。

### 状态与例外

- 主题设置读取失败：使用`跟随系统`，不得影响书签数据加载。
- 系统主题在页面打开期间变化：工作台无刷新切换，并保留当前展开详情与输入状态。
- 浏览器不支持系统主题监听：打开页面时读取一次系统状态，并允许用户手动选择。

### 业务规则与默认值

- 主题是界面偏好，不参与书签导入、导出、快照或撤销导入。
- 四种模式都必须保持相同的信息层级、组件尺寸和功能；不能让浅色版或深色版成为次等版本。
- 切换动效应克制，并遵循系统“减少动态效果”设置。

### 用例

- 正常：用户在家中选择`浅色`，页面立即变亮；关闭并重新打开浏览器后仍保持浅色。
- 边界：用户正在编辑链接时系统从浅色切换到深色，表单内容、焦点和未保存输入均保持不变。

### 验收标准

- 四个主题模式在界面中可理解且可通过键盘选择。
- 手动浅色和深色选择优先于系统设置，直到用户改回其他模式。
- 所有主题下文字、边框、焦点、错误和标识均清晰可辨。
- 主题切换不重载页面、不改变书签内容，也不丢失当前操作状态。

## 4. `VIEW-THEME-002` 日出日落自动主题

产品状态：`Ready for Delivery`<br>
当前可用性：`Not built`

### 用户问题与价值

用户希望白天自动使用明亮主题，日落后切换到深色主题，不必每天手动调整。

### 包含

- 该模式必须由用户主动选择，不在后台自行开启。
- 首次选择时解释需要位置才能计算当地当日的日出与日落，并在需要时请求浏览器位置权限。
- 获得许可后，根据当前日期和当地日出／日落切换：日出至日落使用浅色，其余时间使用深色。
- 主题入口中显示当前自动状态及下一次切换时间，例如“深色 · 日出 06:01 后切换”。
- 位置和时间计算只用于本地主题切换，不用于分析、同步或向第三方传输。

### 不包含

- 天气、温度、城市推荐或出行信息。
- 后台持续追踪位置；无必要时不得反复请求定位。
- 未经用户确认用 IP 地址推断位置。

### 状态与例外

- 用户拒绝或撤销位置权限：保持当前主题并提示自动模式不可用，提供`浅色`、`深色`和`跟随系统`选择；不得反复弹出权限请求。
- 暂时无法读取位置：使用最近一次有效的本地自动主题结果；若从未成功，回退到`跟随系统`并说明原因。
- 日期、时区或夏令时变化：下次打开新标签页时重新评估，并更新下一次切换时间。
- 页面跨越日出／日落边界保持打开：在边界到达时切换，不要求刷新。

### 可靠性与来源

日出日落时间是根据用户授权的位置和设备日期计算的近似值，可能因位置精度、时区或设备时间错误产生偏差。界面只显示分钟级结果，不暗示气象级精度。

### 用例

- 正常：用户允许定位，日落后工作台自动从浅色切换为深色，并显示次日日出切换时间。
- 边界：用户拒绝定位；系统不启用伪自动模式，而是回退到跟随系统并提供明确选择。

### 验收标准

- 自动模式只有用户主动选择后才请求位置。
- 拒绝定位不会影响任何书签、导入、导出或手动主题功能。
- 日出／日落边界到达后无需刷新即可更新主题。
- 位置数据不会被包含在书签备份文件中，也不会发送给第三方。

## 5. `PLAT-FIREFOX-001` Firefox 桌面支持

产品状态：`Ready for Delivery`<br>
当前可用性：`Partial / Unverified`

### 用户问题与价值

用户可能在家中使用 Firefox，需要同一套新标签页书签工作台，而不被迫改用 Chrome。

### 包含

- 支持当前 Firefox 桌面稳定版；移动版 Firefox 不在本功能范围内。
- 在 Firefox 新标签页展示同一工作台，并保持分类、分组、链接、打开行为、导入／导出、展开详情和主题功能一致。
- Firefox 与 Chrome 分别保存各自浏览器内的数据；不承诺自动同步。
- 用户可以通过 JSON 备份／导入在两个浏览器之间手动迁移数据。
- 工具栏入口、后台生命周期、权限说明与安装包必须使用 Firefox 可接受的形式。

### 不包含

- Firefox Android、Safari 或浏览器之间的实时同步。
- 绕过 Firefox 扩展签名要求。
- 两个平台像素级完全一致；允许遵循各浏览器原生焦点、菜单和权限提示。

### 当前兼容结论

- `chrome_url_overrides.newtab`、存储与常用 tabs 能力在 Firefox WebExtensions 中存在兼容路径。
- 当前 Manifest 只声明 `background.service_worker`，Firefox 不支持该后台形式，因此不能视为完整兼容。
- 当前工具栏入口使用 Chrome 专属的新标签页地址，在 Firefox 中需要使用 Firefox 可接受的入口。
- 当前 Manifest 缺少 Firefox Manifest V3 签名所需的稳定扩展标识及 Firefox 数据收集声明，尚不具备正式分发条件。

### 状态与例外

- Firefox 首次确认新标签页替换：遵循浏览器原生提示，不设计绕过步骤。
- 另一扩展接管新标签页：说明当前工作台未生效，不删除本地数据。
- Firefox 不支持某个非核心辅助能力：提供等价退化体验，核心数据和打开行为不得失效。
- 从 Chrome 导出的 JSON 在 Firefox 导入：遵循现有追加／合并、冲突预览、快照与撤销规则。

### 用例

- 正常：用户在 Firefox 桌面版加载扩展，新建标签页后看到工作台，并导入从 Chrome 导出的 JSON。
- 边界：用户拒绝 Firefox 的新标签页替换确认；扩展保留数据并提供重新启用说明，不重复打扰或清空内容。

### 验收标准

- Firefox 桌面稳定版能够安装测试构建，且扩展管理页无阻塞错误。
- 新标签页、工具栏入口、分类／分组／链接管理与打开规则均可用。
- JSON 导入、备份导出、导入撤销与冲突保护在 Firefox 中通过同等验收。
- Firefox 与 Chrome 分别验证浅色、深色、系统和日出日落主题。
- Firefox 中不存在 Chrome 专属地址导致的空白页或失败导航。
- 发布前满足 Mozilla 对 Manifest V3 扩展 ID、数据收集声明和签名的要求。

## 6. 交付给实现 agent 的不可变约束

1. 不重做用户已认可的分组网格与整体工作台结构。
2. 展开详情默认关闭，且查看详情绝不等同于打开链接。
3. 不批量请求全部网站图标，不使用第三方 favicon 聚合服务。
4. 显式浅色主题必须存在；默认仍跟随系统，以保持升级连续性。
5. 日出日落模式必须自愿启用、最少使用位置、拒绝后可正常使用其他主题。
6. Firefox 支持必须以真实 Firefox 验证为准，不以“代码看起来兼容”代替运行验收。
7. 跨浏览器适配不得削弱现有追加导入、快照、撤销、修订冲突和备份机制。
