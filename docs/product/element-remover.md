# Element Remover 产品定义

文档状态：产品定义来源（Source of Truth）<br>
产品状态：MVP `Ready for Delivery`；网络请求拦截 `Defining`<br>
当前可用性：`Not built`<br>
适用版本：MVP 1.0<br>
最后更新：2026-10-18

> 本文定义用户可见的产品行为，不规定框架、存储结构、选择器算法、实现顺序或工期。实现 agent 不得用技术便利改变本文的确认规则。

## 1. 产品定位

### 用户

经常访问固定网站，希望移除广告、遮挡内容、造成视觉刺激或长期无用页面区域的 Chrome 用户。

### 问题

- 页面中的广告、浮层、推荐区和无用模块会干扰阅读与操作。
- 浏览器开发者工具只能临时删除节点，刷新后不会保留。
- 现有内容过滤器的元素选择流程偏向一次创建一条规则，连续清理多个元素成本高。
- 依赖位置索引的选择器会在列表内容变化后命中错误元素，造成误删。
- 用户需要知道当前哪些内容被规则处理，并能安全恢复。

### 产品承诺

用户可以像使用元素检查器一样在网页上连续选择多个元素，一次确认后按域名与路径保存规则；再次访问相同范围时，扩展自动移除或隐藏目标。发生误匹配时，用户可以通过 Debug 标记定位、恢复并停用规则。

### 与相邻方案的区别

- 不是完整广告拦截器或 uBlock Origin 的替代品。
- MVP 处理已经进入页面的 DOM 元素，不拦截网络请求。
- 不是网页编辑器，不保存修改后的网页副本。
- 不要求普通用户理解或手写 CSS Selector、XPath 或过滤器语法。
- 数据仅保存在当前浏览器本地，不做账号或跨设备同步。

## 2. 核心场景

1. 用户在常用网站进入选择模式，连续选择广告区、推荐区和无用侧栏，一次保存。
2. 用户担心删除节点破坏页面，改用“隐藏”保存目标。
3. 用户重新访问相同域名和路径，规则自动生效。
4. 页面结构变化导致规则误匹配，用户通过 Debug 标记发现并恢复元素。
5. 用户从扩展面板恢复当前页面规则，或在设置页管理所有网站规则。

## 3. 核心价值闭环

```text
打开常用网页
  → 进入元素选择模式
  → 连续选择一个或多个目标
  → 预览移除或隐藏结果
  → 确认作用范围并追加保存
  → 再次访问时自动应用
  → 通过角标与 Debug 验证结果
  → 误匹配时恢复并停用规则
```

闭环成立的必要条件：选择准确、规则不会覆盖旧规则、作用范围可理解、自动执行不会扩大目标、恢复路径可靠。

## 6. 功能规格

### 6.1 `SELECT-PICK-001` 连续多元素选取

产品状态：`Ready for Delivery`<br>
当前可用性：`Not built`

#### 用户问题与价值

用户需要在一个页面中连续清理多个区域，不希望每选一个元素就退出、保存并重新启动选择器。

#### 主流程

1. 用户从扩展面板进入选择模式。
2. 鼠标经过页面元素时，扩展高亮当前候选目标。
3. 用户单击，将当前节点加入待处理列表；页面原有点击行为不触发。
4. 选择模式保持开启，用户继续选择其他元素。
5. 已选择目标显示编号和选中状态；再次单击可取消该目标。
6. 用户进入批量预览，检查全部目标。
7. 用户确认后进入范围确认并保存。

#### 业务规则与默认值

- 只选取鼠标实际指向的节点，不自动提升到父级或扩展到相似节点。
- 父子节点都被选择时提示包含关系，但不得擅自删除任一选择。
- `Esc` 退出选择模式；退出前已有未保存选择时，需要明确放弃或返回。
- 待处理列表允许单独取消目标，以及为单个目标切换处理方式。
- 选择模式不能触发链接跳转、按钮提交或页面拖拽。
- 不要求用户查看或编辑选择器文本。

#### 边界状态

- 不支持的浏览器页面：明确显示“此页面不支持元素选择”。
- 跨域 iframe、封闭 Shadow DOM 或权限不足区域：候选高亮不得假装可保存；说明无法处理的范围。
- 页面在选择过程中重建目标：将失效选择标记为“需要重新选择”，不保存旧引用。

#### 验收标准

- 一次选择会话可加入至少两个不同目标，并一次确认保存。
- 选择一个子节点不会自动选中或处理父节点。
- 取消单个目标不影响同批其他目标。
- 退出选择模式后网页恢复正常点击行为。
- 不支持区域有明确反馈，不出现无响应按钮。

### 6.2 `ACTION-APPLY-001` 移除与隐藏

产品状态：`Ready for Delivery`<br>
当前可用性：`Not built`

#### 用户问题与价值

删除 DOM 节点最彻底，但部分网站脚本依赖节点存在；用户需要可选的更保守方式。

#### 业务规则与默认值

- 默认方式为“移除”：目标从当前页面结构中移除。
- 可选方式为“隐藏”：目标保留在 DOM 中，但不再显示，也不保留明显视觉占位。
- 批量确认时可以统一选择方式，也可以逐项覆盖。
- 为减少广告或高亮区域短暂闪现，即使最终执行移除，也应尽早抑制目标的可见性。
- 移除目标后如果页面仍被滚动锁定，只能提供“恢复页面滚动”建议操作；不得默认修改未选中的父级样式。

#### 用例

- 正常：用户以默认“移除”处理广告和侧栏，再次访问时它们不出现。
- 边界：移除某个弹窗后页面功能异常，用户恢复该规则并改为“隐藏”。

#### 验收标准

- 新选择默认显示为“移除”。
- 用户可以在保存前将任一目标改为“隐藏”。
- 隐藏目标仍保留在页面结构中，移除目标不保留在页面结构中。
- 处理方式始终以文字显示，不能只靠图标或颜色区分。

### 6.3 `RULE-SCOPE-001` 域名与路径范围

产品状态：`Ready for Delivery`<br>
当前可用性：`Not built`

#### 业务规则与默认值

- 默认作用范围由精确主机名与路径组成，例如 `news.example.com/article/*`。
- 默认不扩展到兄弟子域名。
- 查询参数始终不参与范围匹配。
- 普通页面锚点不参与匹配。
- 明显承担客户端路由作用的 `#/route` 或 `#!/route` 作为路径参与匹配。
- 路径尾部斜杠等不改变页面含义的形式差异应归一处理。
- 明显的纯数字 ID、UUID、长随机串或哈希片段可以建议泛化为单段通配范围。
- 年份、语言代码、`settings`、`dashboard` 等有稳定语义的片段不得自动泛化。
- 无法可靠判断动态片段时使用精确路径，不进行扩大匹配。

#### 用户可见范围选项

- 仅当前路径。
- 系统建议的同类路径。
- 当前主机名的全部路径。

保存前必须展示最终范围；自动判断只生成建议，不能隐藏在后台。

#### 验收标准

- `?from=home` 等查询参数变化不影响规则生效。
- 普通 `#comments` 变化不影响规则生效。
- `#/dashboard` 与 `#/settings` 能作为不同路由处理。
- 路径被泛化时用户能看到通配位置并切换回精确路径。

### 6.4 `RULE-MATCH-001` 稳定匹配与安全失败

产品状态：`Ready for Delivery`<br>
当前可用性：`Not built`

#### 可靠性要求

规则应优先依据稳定唯一标识、有语义的属性、元素类型和稳定祖先范围。动态构建类名、随机字符串和位置索引只能作为低可靠性信息；`nth-child`、`nth-of-type` 等位置索引不得成为首选依据。

保存时记录目标的复核特征和预期匹配范围。重新访问时：

- 预期一个且实际命中一个：正常执行。
- 预期一个但实际命中多个：暂停规则并标记“需要复核”。
- 暂时无匹配：不报错打扰用户，规则标记为“当前未匹配”。
- 用户明确创建同类目标规则时，允许数量在确认范围内变化。
- 页面动态重建同一目标时更新当前实例，不把重复重建累计为多个历史结果。

#### 用户可见可靠性状态

- 精确
- 可能变化
- 需要复核
- 当前未匹配

#### 验收标准

- 列表前方新增或删除项目后，规则不得仅因旧索引而处理另一个无关项目。
- 匹配结果从一个异常扩大到多个时，不执行批量误删。
- 暂时无匹配不会删除规则或反复弹出错误。
- 设置页能显示需要复核的规则。

### 6.5 `RULE-SAVE-001` 批量追加保存

产品状态：`Ready for Delivery`<br>
当前可用性：`Not built`

#### 业务规则与默认值

- 保存前展示分类后的目标总数、移除数量、隐藏数量和作用范围。
- 新规则追加到已有规则，不覆盖历史记录。
- 检测到完全重复的规则时提示并跳过重复项。
- 整批保存保持一致结果；不得无提示地只保存一部分。
- 保存失败时保留本次选择和用户调整，允许重试或取消。
- 替换已有规则必须是用户明确触发的独立操作，并展示被替换对象。

#### 验收标准

- 连续保存两批规则后，两批都能在管理界面看到。
- 重复保存同一目标不会静默生成冲突规则或覆盖旧规则。
- 保存失败后用户无需重新选择全部目标。

### 6.6 `RULE-MANAGE-001` 当前页面规则与恢复

产品状态：`Ready for Delivery`<br>
当前可用性：`Not built`

#### 面板内容

- 当前主机名与路径范围。
- 当前页面已处理元素总数，以及移除/隐藏数量。
- 进入元素选择模式的主要操作。
- Debug 模式开关。
- 当前页面命中的规则列表。
- 打开全部网站规则管理页的入口。

每条规则显示元素简述、作用范围、处理方式、当前匹配数量、可靠性状态和启用状态。

#### 恢复与删除

- “恢复显示”停用规则并保留记录，以便之后重新启用。
- “删除规则”永久删除记录，置于次级危险操作并要求确认。
- 隐藏元素应尽量即时恢复。
- 移除元素按 `STATUS-DEBUG-001` 的原位恢复与刷新回退规则处理。
- 一个规则匹配多个元素时，恢复操作必须预先显示影响数量。

#### 验收标准

- 用户无需进入设置页即可恢复当前页面的一条规则。
- 恢复不会永久删除规则。
- 永久删除与恢复具有不同文案、位置和确认层级。
- 多目标规则恢复前明确显示将恢复的元素数量。

### 6.7 `RULE-MANAGE-002` 全部网站规则管理

产品状态：`Ready for Delivery`<br>
当前可用性：`Not built`

#### 信息结构

```text
主机名
└── 路径范围
    └── 元素规则
```

#### 包含

- 展开主机名查看路径范围和元素规则。
- 单独启用、停用或永久删除规则。
- 批量恢复一个路径范围。
- 批量恢复一个主机名。
- 查看规则处理方式、匹配状态和需要复核状态。
- 打开对应网页并重新选择目标。

#### 业务规则

- “恢复路径”与“恢复网站”默认只停用规则，不删除数据。
- 批量删除必须显示规则数量和影响范围并二次确认。
- 本地数据读取失败时不得生成空数据覆盖已有规则。

#### 验收标准

- 用户能从一个页面找到任意网站的已保存规则。
- 批量恢复不会永久删除规则。
- 需要复核和当前未匹配的状态可被识别，不只靠颜色表达。

### 6.8 `STATUS-BADGE-001` 当前页面处理数量

产品状态：`Ready for Delivery`<br>
当前可用性：`Not built`

#### 业务规则

- 角标显示当前页面实际被处理的元素实例数，不显示规则数。
- 同一规则匹配五个元素时计为五个。
- 同一动态目标被页面反复重建时，不累计为不断增长的历史次数。
- 数量为零时不显示角标。
- 超过 99 时显示 `99+`。
- 恢复、重新匹配或动态内容变化后更新数量。
- 不支持的页面不显示误导性数量。

#### 验收标准

- 两条规则分别处理 1 个和 4 个元素时角标显示 `5`。
- 恢复一个单目标规则后角标减少一。
- 页面反复重建同一广告位不会让角标无限增长。

### 6.9 `STATUS-DEBUG-001` Debug 标记与原位恢复

产品状态：`Ready for Delivery`<br>
当前可用性：`Not built`

#### Debug 状态

- 默认关闭。
- 仅对当前标签页临时生效，关闭标签页后结束。
- 开启后，每个被处理目标的原始位置显示低干扰标记。
- 标记不参与页面布局；收起状态不拦截网页正常点击与滚动。
- 标记显示规则编号和移除/隐藏类型；重叠标记聚合显示数量。
- 悬停、键盘聚焦或点击标记时显示恢复操作，不能只依赖 hover。

#### 直接恢复

执行移除时，在不影响布局的前提下保留定位锚点，并在当前页面会话中保留原始节点引用。用户选择“恢复显示”时：

1. 停用对应规则，但不删除规则。
2. 优先将原始节点放回定位锚点。
3. 成功后移除 Debug 标记并更新角标。
4. 显示短暂成功反馈和“撤销恢复”。

#### 刷新回退

如果页面已经重建父级、移除锚点或原位恢复不再安全：

1. 先停用对应规则。
2. 记录当前 URL、稳定内容锚点、相对偏移、滚动容器和可恢复焦点。
3. 明确提示刷新可能丢失未提交内容，不得静默刷新。
4. 用户确认后刷新页面。
5. 页面重新加载且不再执行该规则。
6. 优先按内容锚点恢复浏览位置；失败时退回原始滚动距离，并说明未能精确定位。
7. 对延迟加载引起的布局变化最多进行一次位置校正，避免持续抢夺用户滚动控制。

如果用户在目标已被移除后才开启 Debug，使用“开启并刷新”重新定位目标，并遵守相同的刷新提示规则。

#### 单实例与整条规则

- “恢复并停用规则”是持久主操作，规则匹配多个实例时恢复全部并显示影响数量。
- “仅本次显示此元素”可以作为当前页面会话的次级操作，不改变永久规则。

#### 验收标准

- Debug 关闭时页面不显示任何调试标记。
- 标记可通过鼠标和键盘访问。
- 直接恢复成功时不刷新页面，元素回到原位置且规则被停用。
- 无法安全原位恢复时，在用户确认后刷新，并尽量返回原浏览位置。
- 刷新前明确提示未提交内容风险。
- 多实例规则不会以“恢复一个”的文案误导用户。

### 6.10 `NETWORK-BLOCK-001` 网络请求拦截（后续）

产品状态：`Defining`<br>
当前可用性：`Not built`

#### 已确认边界

- Manifest V3 可以通过声明式网络规则拦截部分广告或资源请求。
- DOM 元素选择与网络请求规则是不同能力，不能假设选中一个元素就能可靠推导唯一网络请求。
- 当前 MVP 不包含过滤列表、请求日志、网络规则编辑、反广告检测处理或 uBlock Origin 兼容层。
- 实现 agent 不得自行把元素规则转换成网络拦截规则。

#### 待定义

- 规则来源与更新方式。
- 用户自定义规则能力。
- 权限策略与误拦截恢复。
- 支持的资源类型与作用范围。
- 第三方过滤列表许可与兼容范围。

## 7. 明确不做

- 账号、云同步或跨设备同步。
- 完整广告拦截器或 uBlock Origin 功能兼容。
- 当前 MVP 的网络请求拦截。
- 自动修改父级、同级或相似元素。
- 要求用户手写 CSS Selector、XPath 或过滤器语法。
- 静默刷新网页。
- 未经用户确认扩大域名或路径范围。
- 根据一次误匹配猜测并删除目标。
- 导入、导出或订阅第三方规则列表。

## 8. 整体验收场景

### 场景 A：连续清理常用页面

用户进入选择模式，依次选择顶部广告、右侧推荐栏和底部推广区；前两个使用默认“移除”，第三个改为“隐藏”。用户预览后确认同类路径范围。保存后原有规则未被覆盖，刷新页面时三个目标按设定处理，角标显示 `3`。

### 场景 B：动态列表避免误删

用户曾移除列表中的一个特定模块。网站在列表前方插入新内容后，规则不能仅按旧索引删除另一个模块；如果唯一性无法确认，规则暂停并在面板中显示“需要复核”。

### 场景 C：Debug 原位恢复

用户发现规则误删正文区域，开启 Debug 后聚焦对应标记并选择“恢复显示”。扩展停用规则并优先原位放回节点；恢复成功后角标减少，规则仍可在管理页重新启用或删除。

### 场景 D：刷新回退并恢复阅读位置

页面脚本已重建目标容器，无法安全原位恢复。扩展说明需要刷新及未提交内容风险。用户确认后刷新，目标重新出现，页面尽量回到原阅读位置；无法精确定位时给出明确提示。

### 场景 E：路径范围

用户在 `/project/12345/settings?tab=members` 保存规则。系统建议范围 `/project/*/settings` 并在保存前展示。规则在项目 ID 改变及查询参数变化后仍生效，但不作用于 `/project/12345/overview`。

## 9. 实现与审查交接

实现 agent 必须先阅读本文与 [`element-remover-ui.md`](element-remover-ui.md)。实现不得自行加入 `NETWORK-BLOCK-001`，不得以单元素选择替代批量流程，也不得把恢复实现成永久删除规则。

代码审查至少验证：

- 多元素连续选择与批量追加保存。
- 子节点选择不会扩大到父级。
- 查询参数忽略、动态路径建议和范围确认。
- 列表结构变化后的安全失败。
- 移除与隐藏的差异。
- 当前页面面板与全部规则管理。
- 角标按元素实例计数。
- Debug 直接恢复、刷新回退和浏览位置恢复。
- 键盘、焦点、权限不足和不支持页面状态。
